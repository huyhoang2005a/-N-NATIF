# @r2m/db

Drizzle schema, migrations and seeds for R2M V5.

## Scope (Phase 1)

Only the bounded contexts implemented so far are modeled here:

- Identity & Organization (`user_account`, `user_identity`, `user_profile`, `organization`,
  `organization_domain`, `organization_member`)
- Verification — **organization verification only** (`organization_verification_request`,
  `verification_document` scoped to organization requests)
- Platform Operations (`notification`, `audit_log`, `outbox_event`, `idempotency_key`)

The full `docs/spec/schema_v5_production.dbml` defines ~60 tables across 8 bounded
contexts. Later phases add their tables in a new `schema/<bounded-context>.ts` file plus a
new numbered migration — never by altering tables already in production data, and never by
jumping ahead of the phase order in CLAUDE.md / architecture plan §21.

`verification_document` will gain a nullable `author_verification_request_id` column and
the "exactly one of the two FKs is non-null" check constraint in the Phase 2 migration,
once `author_profile` / `author_verification_request` exist.

## Commands

```bash
pnpm --filter @r2m/db generate   # drizzle-kit: diff schema/ -> migrations/*.sql
pnpm --filter @r2m/db migrate    # apply migrations/ then manual-migrations/
pnpm --filter @r2m/db seed       # seed a platform admin + sample ACTIVE organization
```

## Two migration layers

1. `migrations/` — generated by `drizzle-kit generate` from `src/schema`. Never hand-edit.
2. `manual-migrations/` — hand-written SQL for constructs drizzle-kit does not manage
   (partial unique indexes, triggers). Applied by `src/migrate.ts`, which tracks applied
   files in a `_manual_migration` table so each file runs exactly once.
